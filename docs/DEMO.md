# Five-minute walkthrough

This is a new September 2026 prototype inspired by prior RA experience. Do not describe it as something built in college.

- **0:00–0:35 — The problem:** Explain the proposal, small-budget, calendar, and flyer busywork.
- **0:35–1:30 — Create:** Open the local workspace. Choose the fictional s'mores example, click Fill in event, and edit the title or activity. State that the current draft provider is local templates while live AI integration is deferred. Dictate only if browser support and permission have been tested beforehand.
- **1:30–2:25 — Validate:** Replace one outcome with “Residents will be able to: understand community.” Run the checks. Explain the concrete failure messages and why code checks the draft. Correct the outcome and recheck.
- **2:25–3:15 — Budget:** Show the estimated supplies. Increase a cost above the event/semester allowance to demonstrate the block, then correct it. Explain that prices are estimates.
- **3:15–4:10 — Human review:** Show three local flyer directions and the pending Calendar/Canva statuses. Confirm review and approve locally. Explain exactly what happened: proposal saved and estimated funds reserved, with no booking or external creation.
- **4:10–4:40 — Persistence:** Open My events and the Semester budget. Demonstrate that actual spending replaces the estimate using a clearly fictional test event.
- **4:40–5:00 — Evidence and next step:** Report only the actual test result in VALIDATION.md. An LLM evaluation and time-saving measurement are not yet available. Next connect a real structured-output provider, Google Calendar, and Canva behind separate approval gates.

For a production-job demo, integrate and test the real provider before claiming agent tool calling. Keep a log of genuine model mistakes after integration; intentional test failures are not real AI mistakes.
